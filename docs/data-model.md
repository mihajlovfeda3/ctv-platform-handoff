# Модель данных

Сценарий — возможный способ применения технологии. Кейс — отдельный пример фактического применения. Даже при отсутствии кейса сценарий может храниться в каталоге. Синтетические кейсы первой итерации являются исключительно вымышленными учебными записями.

## Восемь слоёв

| Слой                       | Таблицы и связи                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------- |
| Бизнес-ландшафт            | `business_nodes`: направление, процесс, этап; self-FK `parent_id`; защита от самоссылок и циклов  |
| Классы задач               | `task_classes` → бизнес-узел; `scenario_tasks` M:N со сценариями                                  |
| Сценарии                   | `scenarios` → функциональная группа, бизнес-узел, источник; независимые связи с остальными слоями |
| Технологический справочник | `technology_directions` → `key_technologies` → `technology_methods`; `scenario_technologies` M:N  |
| Бенчмаркинг                | `benchmark_cases` → организация, необязательное решение; `scenario_cases` M:N                     |
| Решения поставщиков        | `vendors` 1:N `vendor_solutions`; `scenario_solutions` M:N                                        |
| Внутренний портфель        | `internal_projects` с видом объекта и организацией; `scenario_projects` M:N                       |
| Типы эффектов              | `effect_types`; `scenario_effects` M:N                                                            |

Дополнительные сущности: `functional_groups`, `organizations`, `sources`, `scenario_assessments`, `import_batches`, `import_rows`. Всего 23 таблицы.

## Идентичность и происхождение

Основные объекты имеют UUID, `is_synthetic`, `source_id`, `created_at`, `updated_at`. Источники хранят тип, название, необязательный URI и собственные метаданные. Таблицы связей также имеют источник, временные метки и признак синтетики. Их составные первичные ключи исключают повторы одной связи.

У сценария обязательна пара `origin_namespace + external_id` с уникальным индексом. Внешний ID — строка: ведущие нули не теряются. UUID синтетических записей и импорта воспроизводимы через SHA-256 (UUID v8). Импорт использует однозначное кодирование пары namespace/ID. UUID новых объектов вне импорта генерирует PostgreSQL. История происхождения импорта содержит сопоставление полей и исходные строки в БД; корпоративные файлы в Git не требуются.

## Сценарий

Поля: название, описание, необязательное обоснование, функциональная группа, бизнес-процесс, бизнес-вызов, источник, статус реализации (`yes`, `no`, `unknown`), OODA (`observe`, `orient`, `decide`, `act`), технологический тренд и предложение проекта. Сценарий может иметь несколько методов технологий, задач, эффектов, кейсов, решений и внутренних проектов.

Бизнес-узел и группа пока являются основными привязками 0..1. Дополнительные привязки можно вводить отдельной M:N-таблицей без перепроектирования остальных слоёв. Связи кейсов с решениями и задач с процессами намеренно минимальны; многозначность этих связей — решение следующей итерации.

## Оценки

`scenario_assessments` хранит отдельные записи:

| `metric`                   | Значение                                       |
| -------------------------- | ---------------------------------------------- |
| `market_maturity`          | Целое 1–5                                      |
| `organizational_readiness` | Целое 1–7                                      |
| `business_impact`          | Целое 1–3                                      |
| `application_trl`          | Целое 1–9, только явно заданный уровень        |
| `solution_potential`       | Качественный текст, числовая шкала не вводится |

Диапазон TRL 1–9 используется как базовый контракт уровней готовности; трактовку отраслевого TRL и допустимых подтверждений нужно согласовать в ТЗ №2. TRL не пересчитывается в РЗ или ОГ.

Каждая оценка имеет источник (nullable, если ещё не установлен), дату оценки, обязательный организационный контекст, `is_current`, признак синтетики и временные метки. Partial unique index допускает только одну текущую оценку для комбинации сценарий/показатель/контекст. Исторические оценки сохраняются с `is_current=false`. Числовые границы и непустое качественное значение контролируются CHECK-ограничениями БД. Отсутствие оценки означает неизвестное значение, а не ноль. Шкалы не располагаются в справочнике технологий.

Признак реализации хранится в сценарии как минимальное поле ТЗ №1. Переход к статусам реализации по организациям и периодам следует согласовать перед многокомпанейной загрузкой.

## Синтетический набор

Некоторые сценарии имеют несколько методов, некоторые не имеют кейса или оценки. Все сущности и связи отмечены `is_synthetic=true`. Seed `20261027`, версия генератора `synthetic-v1`.
