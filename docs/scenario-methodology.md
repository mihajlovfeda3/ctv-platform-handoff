# Содержание сценариев ЦТВ

Сверка выполнена по предоставленным «Формулировки в ЦТВ (1).pdf»,
«Справочник цифровых технологиий ЦТВ (1).pdf», «Справочники.xlsx» и структуре
«Сценарии_ЦТВ.xlsx». Записи последней книги в демонстрационную базу не импортируются.

## Функциональная группа

Лист «Справочник ФГ» подтверждает 31 наименование, ранее сохранённое в
business_directions. Канонические записи добавлены в functional_groups
с теми же стабильными UUID. Старые таблицы и четыре учебные ФГ сохранены.
scenario_functional_groups задаёт одну проекцию для списка, карточек и фильтра.
Она учитывает точное совпадение наименований. При противоречии двух признанных
значений проекция не выбирает одно из них. Неопознанная старая ФГ также требует
сопоставления. Исходные значения доступны в БД.

В XLSX «Cнабжение» начинается с латинской C. Указано явное соответствие
существующему «Снабжение». Разделитель | в составных ФГ сохранён как часть
одного справочного значения, а не как второе измерение.

## Технологии и дополнительные поля

97 троек направления, технологии и метода взяты из листа «Справочник технологий»
с удалением только окружающих пробелов. Подписи радара сохранены через два явных
соответствия — «Робототехника и аддитивные технологии» и «Робототехника и 3D-печать»,
«Беспилотные авиационные системы» и «Беспилотные воздушные средства».
Опечатки в названиях методов источника автоматически не исправляются.

Используются существующие description и business_challenge.
Добавлены необязательные business_effect и business_challenge_description.
Оба поля поддержаны контрактами API и импорта. Тип эффекта остаётся отдельной связью.

## Синтетические данные

16 согласованных профилей по пяти объектам дают 80 различных применений.
Для нагрузочного набора профили повторяются на явно вымышленных площадках,
указанных в описании. ID сценариев и оценки сохраняются.
Обновляются только распознанные записи генератора с совпадающими исходными
полями и происхождением. Отредактированные записи и чужие связи сохраняются.
Исправляются собственные демонстрационные связи с технологиями, задачами и эффектами.
Связи с кейсами, решениями и проектами сохраняются.

Повторный seed выполняется транзакционно, не добавляет записи поверх существующих.
Оценки существующих сценариев сохраняются.
Новые назначения организационных блоков остаются неизвестными, поскольку
источник не устанавливает соответствие блока и ФГ.

## Ограничения источников

PDF использует «Закупки и снабжение», тогда как XLSX содержит две разные ФГ.
Приоритет в этой версии отдан явному справочнику XLSX, автоматического объединения нет.
В материалах есть отметка об автоматическом статусе реализации, но нет формулы
его зависимости от ОГ. Статус не пересчитывается. Для проверки доступны
сочетания статуса и ОГ из scripts/audit-scenarios.ts, без вымышленных порогов.
