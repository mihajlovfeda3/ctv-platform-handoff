# ЦТВ — комплект для продолжения разработки

Независимая копия текущей платформы Next.js / TypeScript / PostgreSQL.
Включены каталог, радар, матрица зрелости, 3D-куб, карточки сценариев и раздел
«Бизнес и задачи», а также снимок всех 80 демонстрационных сценариев.

Начните с этого файла. Устройство проекта и принятые решения — в
[`HANDOFF.md`](HANDOFF.md), инструкции агентам — в [`AGENTS.md`](AGENTS.md)
и [`CLAUDE.md`](CLAUDE.md).

## Получение проекта

Репозиторий: https://github.com/mihajlovfeda3/ctv-platform-handoff (приватный;
владелец добавляет коллег по их GitHub-логинам).

```sh
git clone https://github.com/mihajlovfeda3/ctv-platform-handoff.git
cd ctv-platform-handoff
```

Если получили ZIP, распакуйте его. Внутри есть папка исходников и отдельный
`ctv-platform-handoff.bundle` со всей историей Git. Для продолжения с историей,
из каталога с bundle выполните:

```sh
git clone ctv-platform-handoff.bundle ctv-platform-development
cd ctv-platform-development
```

У локального клона bundle `origin` указывает на файл. Для отправки изменений
в GitHub замените его адрес:

```sh
git remote set-url origin https://github.com/mihajlovfeda3/ctv-platform-handoff.git
```

Затем выполните первый запуск ниже. Папка исходников из ZIP позволяет запустить
приложение и без Git, но для совместной разработки рекомендуется клон.

## Первый запуск

Нужны Node.js 24 LTS с npm и работающий Docker с Compose v2. Git нужен при
клонировании репозитория; распакованный ZIP также можно использовать.
Команды ниже выполняются в корне проекта. Они одинаковы для PowerShell,
Terminal macOS и Linux.

```sh
node scripts/setup-handoff.mjs
npm ci
docker compose up -d --wait
node scripts/restore-handoff.mjs
npm run dev
```

Откройте **http://127.0.0.1:3000/scenarios/radar** или
**http://127.0.0.1:3000/business/landscape**.

`setup-handoff` создаёт только локальную `.env`: собственный случайный пароль,
БД `ctv_handoff`, PostgreSQL на `127.0.0.1:5434`, без облачных доступов. Уже
существующая `.env` сохраняется. Пароль нигде не печатается и не попадает в Git.
Если порт 5434 занят, поменяйте `POSTGRES_PORT` и порт в `DATABASE_URL` вместе.

Восстановление само применяет миграции. Оно заполняет только пустую БД,
сохраняет исходные ID, связи и оценки, затем сравнивает контрольные суммы всех
26 таблиц. Повторное восстановление заполненной БД останавливается с сообщением,
данные не перезаписываются. **Не запускайте `db:seed` для получения переданного
состояния**: используйте готовый снимок.

Если PostgreSQL 17 уже установлен, Docker необязателен: создайте отдельную
пустую БД `ctv_handoff`, настройте свои локальные значения в `.env` и пропустите
команду `docker compose`. Восстановление разрешено только через `127.0.0.1`,
`localhost` или `::1` к БД с окончанием `_handoff` / `_handoff_test`.

Для обычного следующего запуска, без повторного восстановления:

```sh
docker compose up -d --wait
npm run dev
```

Остановка собственного Docker-сервиса: `docker compose stop`. Не добавляйте
`down -v`, если хотите сохранить локальную БД.

## Проверки

```sh
node scripts/restore-handoff.mjs --verify-only
npm test -- tests/handoff-restore.test.ts
npm run check
```

`--verify-only` сравнивает БД с исходным снимком, ничего не записывая. После
собственных изменений данных ожидаемое несовпадение не означает поломку сайта.
`npm run check` включает lint, TypeScript, Vitest и production build. Перед
изменением кода учитывайте уровень проверок из `AGENTS.md`.

Для целевых браузерных проверок на готовой production-сборке:

```sh
npm start -- --port 3002
```

В другом терминале:

```sh
npm run test:e2e -- tests/browser/business.spec.ts --project=1440 --grep "layout 1440"
```

Для куба используйте `cube-integration.spec.ts` или `cube-shell.spec.ts`, для
сценариев — соответствующие spec в `tests/browser`. Полный E2E-набор и 2500
сценариев запускаются по основаниям из `AGENTS.md`, а не при первом знакомстве.

## Частые проблемы

- Нет подключения к Docker: запустите Docker Desktop / Docker daemon.
- Соединение с БД отклонено: проверьте `docker compose ps`, порт и `DATABASE_URL`.
- Скрипт отказывается восстанавливать БД: проверьте локальный адрес и суффикс
  имени. При заполненной БД создайте новую пустую, не удаляйте нужные данные.
- Порт 3000 занят: `npm run dev -- --port 3005`, затем откройте этот порт.
- На корпоративном компьютере не поддерживается WebGL: куб покажет сообщение
  и сохранит доступ к списку сценариев; остальные представления доступны.

## Доступы и публикация

Это репозиторий для разработки, без подключения к Render. В комплект не входят
облачные логины/пароли, локальные `.env`, `node_modules`, `.next`, логи и личные
материалы. Общей опубликованной версией и её БД управляет только исходный
владелец. Изменения в этой копии не публикуются туда автоматически.

Исходная версия приложения: `6fd4fae8c0f98b51cb4117c8d2852c9dbae3d26e`.
Подробности происхождения данных — `handoff/manifest.json`.
