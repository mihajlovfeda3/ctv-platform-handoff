# Контракт структурированного импорта

CLI работает локально. По умолчанию — `--dry-run`, без обращения к БД. Только явный `--apply` записывает валидный пакет. Поддерживаются UTF-8 CSV с BOM или без него и JSON-массив объектов; лимиты: 10 МБ и 10 000 записей. Ошибка структуры файла останавливает разбор.

```text
npm run import -- <input.csv|input.json> <mapping.json> <options.json> [--dry-run|--apply]
```

## Явное сопоставление

`mapping.columns` задаёт направление **поле модели → имя входной колонки**. Обязательны `externalId`, `name`, `description`. Заголовки CSV должны быть непустыми и уникальными; строки должны иметь одинаковое число колонок. Повтор использования одной колонки для разных полей запрещён. Сопоставленные, но отсутствующие колонки являются ошибкой. Неназначенные входные поля остаются в raw-строке.

```json
{
  "columns": {
    "externalId": "Номер",
    "name": "Название",
    "description": "Описание",
    "functionalGroupId": "Группа",
    "application_trl": "TRL",
    "organizational_readiness": "Готовность"
  },
  "references": {
    "functionalGroupId": {
      "Учебная группа": "00000000-0000-4000-8000-000000000001"
    }
  },
  "delimiter": ";"
}
```

UUID в примере условный: перед `--apply` используйте существующую запись справочника. Текстовые значения ссылок не создают справочники автоматически. `references` предоставляет явные таблицы сопоставления для группы, бизнес-узла и методов технологий. Для нескольких методов используйте строку с разделителем `|`. Внешние ключи БД проверяют существование ссылок, а ошибка откатывает пакет целиком.

Дополнительные поля: `rationale`, `businessNodeId`, `businessChallenge`, `technologyMethodIds`, `market_maturity`, `organizational_readiness`, `business_impact`, `application_trl`, `implementation`, `ooda`, `technologyTrend`, `projectProposal`. Статус принимает `yes`, `no`, `unknown`. Нераспознанный статус остаётся `unknown` с предупреждением. Невалидный OODA — ошибка контракта. Поля `algorithmText`, `processText`, `stageText`, `tasksText` сохраняются для проверки с предупреждением и не создают автоматических предметных связей.

`options.json`:

```json
{
  "namespace": "synthetic-training-v1",
  "sourceName": "Синтетический учебный источник",
  "synthetic": true,
  "context": "synthetic-lab",
  "assessedAt": "2026-01-01T00:00:00Z"
}
```

`namespace`, `sourceName`, `synthetic`, `context` обязательны. `assessedAt` обязателен, если есть хотя бы одна принятая оценка. Дата загрузки не подменяет дату оценки. Префикс namespace генератора зарезервирован. В первой итерации использовать только синтетические данные.

## Значения и ошибки

- Обязательные ID, название и описание проверяются Zod. Пустые или неверно типизированные обязательные значения блокируют весь пакет.
- Исходные ID остаются строками. Для JSON передавайте ID строкой, если важны ведущие нули; если парсер уже превратил `001` в число, восстановить нули нельзя.
- Пустая, `null`, отсутствующая необязательная оценка означает неизвестное значение; строка из пробелов также считается пустой.
- Принимаются только явные целые уровни в независимых диапазонах РЗ 1–5, ОГ 1–7, влияние 1–3, TRL 1–9.
- Даты, Excel-серийные числа вне шкалы, интервалы, дроби, формулы и текстовые оценки получают предупреждение и не создают оценку. Исходное значение остаётся в `import_rows.raw`. При утрате Excel-метаданных маленькое число не позволяет определить формат исходной ячейки; такой файл требует проверки перед импортом.
- Ошибки: номер записи (после заголовка, начиная с 1), поле, `severity=error`, сообщение. Предупреждения имеют `severity=warning`.
- Сопоставление и диагностика не выполняют формулы, не переходят по ссылкам источника и не интерпретируют содержимое как инструкции.

## Повторы и транзакции

Повтор ID внутри одного файла блокирует пакет. Уникальность в БД определяется парой namespace/исходный ID, а не названием. Повторный импорт существующей пары пропускает её и считает в `skipped`; не перезаписывает описание, связи или оценки. Для обновлений требуется отдельная согласованная политика, её нет в ТЗ №1. Различные namespace означают разные системы происхождения, поэтому один внешний ID в разных namespace допустим.

Проверенный пакет записывается одной транзакцией вместе с источником, batch, исходными строками, оценками и связями. FK-ошибка отменяет весь пакет. Уникальный индекс и `ON CONFLICT` защищают от дублей при конкурентном создании. Локальный JSON-отчёт сохраняется в игнорируемой `.local/import-reports/`; исходные значения в консоль не печатаются. При ошибке файла/JSON/Zod CLI завершает работу с ненулевым кодом; для ошибок строки формирует полный диагностический отчёт.

## Подготовка к XLSX и 11-колоночному источнику

Сам файл `СценарииЦТВ_ММ.xlsx` не был приложен; контракт подготовлен по описанной в ТЗ структуре. Корпоративный набор из 13 строк не загружался. Для него можно явно сопоставить номер, название, описание, обоснование, группу, текст алгоритма, TRL, текст процесса интервью, текст этапа, текст задач и готовность. Текст процесса интервью нельзя автоматически считать каноническим бизнес-процессом, тип алгоритма — готовым методом справочника, а готовность — TRL или рыночной зрелостью.

Интерфейс `ImportAdapter` позволяет добавить XLSX. Адаптер должен сохранять исходный тип ячейки, значение, `numberFormat` и признак формулы. Ячейки TRL с форматом даты отправляются на проверку даже при числовом содержимом. Никаких обратных вычислений «правильного TRL» из Excel-даты нет. Все 13 пустых значений готовности должны остаться неизвестными. UI сопоставления, разрешение неоднозначностей и применение исправлений — следующая итерация.
