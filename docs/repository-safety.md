# Состав репозитория и сохранность данных

Первая итерация сохраняется в приватном GitHub-репозитории. Функциональность приложения при подготовке к загрузке не изменяется.

В Git включаются исходники, SQL-миграции и их метаданные Drizzle, автоматические тесты, lockfile, настройки проекта, Docker Compose, документация и явно синтетические примеры из `fixtures/`.

Не включаются:

- `.env` и другие локальные env-файлы; разрешён только `.env.example` с заглушками;
- пароли, токены, приватные ключи и хранилища учётных данных;
- `node_modules`, сборки, кэши, логи и временные результаты проверок;
- локальные файлы PostgreSQL, SQLite, дампы и резервные копии;
- корпоративные PDF, XLS/XLSX, документы, презентации и исходный UX-прототип;
- реальные исходные наборы и промежуточные материалы импорта.

Входные файлы следует хранить вне репозитория либо в игнорируемой папке `/imports/`. Локальные отчёты и генерируемые тестовые наборы находятся в `.local/`. Новые файлы в `fixtures/` допускаются только после проверки их синтетического происхождения. Расширение JSON/CSV само по себе не доказывает безопасность содержимого.

Перед первой отправкой проверены отслеживаемые файлы, незакоммиченные изменения, история Git, работа исключений и отсутствие локального пароля и типовых сигнатур секретов. Допускаемые SQL-миграции не исключаются правилами для дампов. `.gitignore` не защищает уже отслеживаемые файлы и может быть обойдён `git add -f`, поэтому содержимое будущих коммитов также нужно проверять.

Приватность GitHub не заменяет эти проверки: исходные корпоративные материалы и секреты не должны попадать и в приватный репозиторий.
