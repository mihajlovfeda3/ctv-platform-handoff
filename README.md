# ЦТВ Platform

Первая итерация платформы «Цифровое технологическое видение»: технический фундамент и минимальный сценарный контур. Приложение развивается как общая платформа ЦТВ. Специфика отдельных организаций задаётся данными и контекстом оценок.

Реализованы пять разделов, PostgreSQL-каталог сценариев с серверным поиском и пагинацией, карточка с оценками и связями, CSV/JSON-импорт и генератор синтетических данных. Остальные разделы честно обозначены как подготовленная структура. Подложка будущего радара не отображает аналитические данные.

## Локальный запуск

Требуются Node.js 22.13+ (рекомендуется 24 LTS), npm и Docker с Compose v2. Используйте отдельную локальную БД. Команды выполняются из корня репозитория.

```powershell
npm ci
Copy-Item .env.example .env
# Установите свой POSTGRES_PASSWORD и тот же пароль в DATABASE_URL в .env.
docker compose up -d --wait
npm run db:migrate
npm run db:seed
npm run dev
```

Открыть <http://127.0.0.1:3000/scenarios>. По умолчанию создаются 80 синтетических сценариев с фиксированным seed `20261027`. Все оценки вымышлены. Если порт занят, измените `POSTGRES_PORT` и порт в `DATABASE_URL` одновременно. При использовании специальных символов в пароле закодируйте их для URL.

PostgreSQL доступен только на loopback. Приложение также слушает `127.0.0.1`. Для проверки производственной сборки локально: `npm run build`, затем `npm start`. Никаких облачных ресурсов эти команды не создают. При уже установленном PostgreSQL можно указать отдельную БД в `DATABASE_URL` и пропустить Compose.

## Команды

| Команда                             | Назначение                                                         |
| ----------------------------------- | ------------------------------------------------------------------ |
| `npm run dev`                       | Локальный сервер Next.js                                           |
| `npm run build` / `npm start`       | Сборка / локальный запуск сборки                                   |
| `npm run lint`                      | ESLint                                                             |
| `npm run typecheck`                 | TypeScript                                                         |
| `npm test`                          | Unit и интеграционные тесты на PostgreSQL WASM, без Docker         |
| `npm run test:postgres`             | Те же интеграционные проверки на отдельной настоящей PostgreSQL БД |
| `npm run test:http`                 | Проверки запущенного приложения и API, требуется seed              |
| `npm run check`                     | Lint, типы, тесты, сборка                                          |
| `npm run db:generate`               | SQL-миграция после изменения Drizzle-схемы                         |
| `npm run db:migrate`                | Применение версионированных миграций                               |
| `npm run db:seed -- 80`             | Идемпотентное добавление синтетического набора                     |
| `npm run db:seed -- 2500`           | Расширение набора для будущих проверок радара                      |
| `npm run fixtures:generate -- 2500` | Сохранить JSON-набор в игнорируемую `.local/fixtures/`             |

Для `test:postgres` создайте **отдельную** базу с именем, заканчивающимся на `_test`, и добавьте `TEST_DATABASE_URL` в локальный `.env`. Проверка пересоздаёт схемы `public` и `drizzle` именно в этой тестовой БД. Не направляйте её на базу с нужными данными. Основная БД приложения этим тестом не используется.

Seed не удаляет данные и не перезаписывает существующие записи. При увеличении размера сохраняются ID и значения существующего префикса. Генерация меньшего набора не уменьшает БД.

## Импорт

```powershell
# Проверить синтетический CSV без записи в БД:
npm run import -- fixtures/import.csv fixtures/mapping.json fixtures/import-options.json --dry-run
# Записать после проверки:
npm run import -- fixtures/import.csv fixtures/mapping.json fixtures/import-options.json --apply
# Тот же контракт для JSON:
npm run import -- fixtures/import.json fixtures/mapping.json fixtures/import-options.json --dry-run
```

Повтор одного `namespace + externalId` пропускается, а не перезаписывает запись. Неоднозначные оценки остаются неизвестными. Отчёты находятся в `.local/import-reports/`. XLSX пока не реализован. Подробности: [контракт импорта](docs/import.md).

## Устройство проекта

```text

src/features    каталог, фильтры, контракт и разбор импорта

```

## Границы версии и данные

Нет корпоративной авторизации, редактирования из браузера, XLSX, полноценного радара, матриц или других перспективных представлений. Сервис создания записи доступен внутри серверного слоя; публичного API записи нет. Это локальный фундамент, не production-развёртывание.

Корпоративные PDF, XLSX и исходный UX-прототип не скопированы в репозиторий. `.gitignore` исключает такие материалы, `.env`, локальные импорты, отчёты и данные БД. Не помещайте реальные материалы в `fixtures/` или `public/` и не добавляйте их принудительно в Git. PostgreSQL хранит данные в Docker volume, не в исходном коде. В репозитории нет секретов и адресов корпоративных систем.

Зависимости фиксирует `package-lock.json`; используйте `npm ci`. Для стабильного Drizzle Kit переопределена устаревшая транзитивная версия `esbuild`; генерация миграций проверяется вместе с остальными командами.
