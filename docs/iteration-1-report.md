# Отчёт по первой итерации

Дата: 27 октября 2026. Исходное состояние: пустой Git-репозиторий без исходного кода, БД, API и удалённого адреса. Все приложенные материалы изучены до реализации; приоритеты отражены в [решениях по источникам](source-review.md).

## Реализовано

- Настроены Next.js App Router, React, TypeScript, Tailwind CSS, ESLint, Vitest, PostgreSQL/Drizzle, Zod, lockfile и локальные конфигурации без секретов.
- Созданы 23 таблицы, две версионированные SQL-миграции, UUID, внешние ключи, M:N-связи, метаданные происхождения, защита от повторных внешних ID и циклов бизнес-иерархии.
- Восемь предметных слоёв: бизнес-ландшафт, классы задач, сценарии, технологии, кейсы, решения поставщиков, внутренний портфель, эффекты. Поставщик и решение раздельны; справочник имеет три уровня. Подробности: [модель](data-model.md).
- Независимые оценки РЗ, ОГ, влияния, TRL и качественного потенциала с датой, источником, контекстом и возможностью истории. Нет вымышленных производных формул.
- Воспроизводимый генератор на 80 или 2 500 сценариев с фиксированным seed; все сущности, оценки и связи помечены синтетическими. Есть пропуски оценок, сценарии без кейсов и многозначные технологические связи.
- CSV/JSON-импорт: явное сопоставление, проверки типов/обязательных полей/оценок, сохранение исходных ID и raw-строк, диагностический отчёт, транзакция, create-only политика повторов. [Контракт](import.md).
- Сервисы создания и чтения сценариев, фильтры SQL, пагинация, четыре группы GET API, безопасные HTTP-ошибки.
- Оболочка, боковая навигация, заголовок, поиск, компактные верхние фильтры, таблица каталога, пагинация, самостоятельная карточка, блоки связанных объектов, схематическая подложка радара, загрузка, пустая выдача, неверные фильтры, not-found и ошибка подключения.
- `/overview`, `/scenarios`, `/business`, `/technologies`, `/portfolio` доступны. Три будущих предметных раздела обозначены как подготовленная структура.

## Запуск и состояние среды

Полная инструкция находится в [README](../README.md). Стандартная последовательность: `npm ci` → локальный `.env` → `docker compose up -d --wait` → `npm run db:migrate` → `npm run db:seed` → `npm run dev`. Адрес: `я`.

Docker на машине отсутствует, поэтому запуск через Compose и его healthcheck **не выполнены**. Для фактической проверки использован локальный PostgreSQL 17.10, привязанный к `127.0.0.1:54329`. Его бинарные файлы и данные находятся вне Git, креденшалы — только в игнорируемом `.env`. Раздельные базы использованы для приложения и интеграционных тестов. Это локальная проверка, не внешняя инфраструктура. Приложение не публиковалось.

## Ограничения

1. Docker Compose нужно выполнить на машине с Docker; до этого критерий запуска именно через Compose остаётся неподтверждённым.
2. Сам `СценарииЦТВ_ММ.xlsx` не приложен: его 13 корпоративных записей не импортировались. Описанные в ТЗ проблемные значения проверены на синтетических примерах. XLSX-адаптер пока отсутствует.
3. Радар — только рабочее пространство с подложкой. Нет точек, масштаба, кластеризации, матриц, 3D и остальных аналитических представлений. Проверка 2 500 записей не является тестом производительности радара.
4. Карточка — отдельная страница; контекстный инспектор поверх радара не реализован.
5. Импорт выполняется CLI. Нет UI сопоставления/проверки, обновления существующих записей и автоматического распознавания текстовых справочников. Неизвестная оценка в повторном импорте не обновит уже существующий сценарий: пакет его пропустит.
6. История оценок предусмотрена схемой и чтением, но операции назначения текущей оценки и согласования источника ещё не оформлены отдельным пользовательским процессом. Статус реализации пока относится к сценарию целиком.
7. Нет корпоративной авторизации, production-инфраструктуры, развёртывания и реальных данных. GitHub remote отсутствует: загрузка в GitHub не выполнялась.
8. Конкурентное изменение бизнес-иерархии потребует сериализации. Автоматизированная проверка мобильных viewport и разных браузеров ещё не настроена.
9. ESLint 9 выбран по совместимости с peer-зависимостями текущего Next-конфига. Пакет отмечен upstream как deprecated; переход на ESLint 10 следует выполнить вместе с совместимыми версиями плагинов. Проверки текущей версии проходят.

## Предложения для ТЗ №2

1. Согласовать полный контракт сценария: обязательность группы/процесса/источника, несколько бизнес-привязок, качество формулировок, редактирование и архивирование.
2. Определить процесс ведения оценок: организационные контексты, дата актуальности, история и назначение текущей; отдельно согласовать TRL применения, потенциал и статусы реализации по компаниям.
3. Реализовать полный модуль «Сценарии»: карточку с сохранением выборки, редактирование, технологические/задачные связи и инспектор в компоновке A.
4. Добавить XLSX с метаданными ячеек, предварительным просмотром, ручным сопоставлением справочников и очередью неоднозначных значений. Утвердить политику обновления существующих записей и аудита.
5. Согласовать семантику радара: что означает точка, обработка неизвестной зрелости, размер маркера, контекст оценок, агрегирование и критерии скорости на 2 500+ сценариев.
6. Выбрать первое следующее аналитическое представление после сценарного контура; не включать автоматически весь перспективный набор.
7. Определить роли и доступ перед реальными данными; согласовать закрытый GitHub remote и целевую среду отдельно.
